# 確定後の再変換：調査メモ（2026-10-31）

モックアップの5回のフィードバックで、毎回出た「確定したあとで直したい」（P1 ほか）を、範囲に入れられるかを調べた。

## 結論

**エンジンに手を入れずに作れる見込みがある。ただし、使えるのはアプリが対応している場合だけ。** どのアプリで使えるかは、まだ実機で確かめていない。

## 必要なもの（3つ）

### 1. 確定済みの文字を読み取る → すでにある

アプリ本体に、選んだ文字を読み取って置き換える仕組みがすでにある（AI 変換の機能）。

- `client.selectedRange()` で選択範囲をとる（`azooKeyMacInputController.swift:275` など）
- `client.string(from:actualRange:)` で選んだ文字と前後の文を読む（`azooKeyMacInputController+SelectedTextTransform.swift:36`）

再変換も、同じ呼び出しで選んだ文字を受け取れる。

### 2. 漢字から読みを出す → macOS の機能で代わりが利く

変換エンジン（AzooKeyKanaKanjiConverter）には、漢字かな交じりの文から読みを出す機能がない。macOS に入っている `CFStringTokenizer`（読みの書き起こし）で試したところ、かなり正しく出た。

| 入力 | 出た読み |
|---|---|
| 今日は橋を渡って帰る | きょう・は・はし・を・わたっ・て・かえる |
| 子どもと一緒に出来る | こども・と・いっしょ・に・できる |
| 生憎の雨 | あいにく・の・あめ |
| 東京都に行った | とうきょう・と・に・いっ・た |
| v1.2で起動の不具合を直した | ゔ・2・で・きどう・の・ふ・ぐあい・を・なおし・た |

- 英字と数字は崩れる（v → ゔ、1.2 → 2）。英数字の部分は読みに直さず、そのまま残す必要がある
- 読みが複数ある語（「行った」→ いった／おこなった）は、間違えることがある
- **より確かな方法**：IME が自分で確定した文について、読みと区切りを手元に記録しておく。選ばれた文字が記録と一致すれば、その読みを使う。一致しなければ `CFStringTokenizer` を使う

どちらもエンジンの外でできる。

### 3. 選んだ文字を置き換える → アプリ次第

置き換えには、アプリ側が `NSTextInputClient`（選択範囲の取得と、指定した範囲の置き換え）を実装している必要がある。

- 一般に、AppKit の標準のテキスト欄（テキストエディット、メモ、Pages、Safari の入力欄など）は対応している
- Chrome や Electron 製のアプリ（Slack、VS Code）、ターミナルが対応しているかは、資料では確かめられなかった。**実機で試す必要がある**
- macOS 標準の日本語入力にも再変換がある（「かな」キーを2回押す）。ただ、このアプリでは「かな」キー2回を、選んだ文字の AI 翻訳にすでに使っている（`azooKeyMacInputController.swift:323`）。再変換を呼ぶキーは、別に決める必要がある

## 範囲に入れる場合の形（案）

1. 確定済みの文字を選んで、決めたキーを押すと（またはメニューから）、入力中と同じ見直しの画面が開く
2. 「確定の取り消し」：確定した直後なら、選ばなくても直前の確定をもう一度開ける
3. 対応していないアプリでは何もしない。そのアプリでは使えないことを短く知らせる

## 次に確かめること（実機）

確かめるには、アプリ本体に一時的なデバッグログを足す必要がある（キーを押したときの選択範囲・読めた文字・置き換えの結果を記録する）。`Tools/dev_install_user.sh` で入れ直し、次のアプリで、選択範囲の取得と置き換えができるかを試す。

- テキストエディット、メモ、Safari、Chrome、Slack、VS Code、ターミナル

computer use では、ターミナルと VS Code には文字を打てない（クリックしかできない）。この2つは手で試してもらう必要がある。

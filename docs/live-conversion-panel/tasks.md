# 変換パネル 作業の段階

上から順に進める。各段階は 1 ブランチ。終わったら、ユーザーに `./install.sh` での確認を依頼し、確認項目を伝える。

## P0 準備：設定項目

- `Config` に「変換パネルを使う」（真偽値、既定オフ）を追加し、設定画面にトグルを出す
- 完了条件
  - [x] オフのとき、既存の動作が変わらない（既存テストがすべて通る）
  - [x] `swift test --package-path Core` と `./install.sh --dry-run` が通る

## P1 表示だけ

- `Core` に、変換候補（`Candidate`）から文節の列（読み・変換結果）を作る処理を実装する（付属語を前の語にまとめる）
- `Core` に、パネルの位置を決める純粋関数を実装する（入力：基準の矩形・パネルの大きさ・画面の範囲・前回の上下。出力：位置と上下）。仕様 3. のルールどおり
- `azooKeyMac` に変換パネルのウィンドウを作り、設定がオンでライブ変換中は常に表示する。中身は文節の列だけ（候補リストはまだ出さない）
- キー操作は変えない
- 完了条件
  - [x] 文節のまとめ方のテスト（例：「明日、橋の端を渡る」のような入力で、期待どおりに区切られる）
  - [x] 位置計算のテスト（下に出る／下端で上に出る／一度上に出たら戻らない／右端で左にずれる）
  - [x] 実機で打つと、読みと区切りがパネルに出る（ユーザー確認）

## P2a 調査：途中の文節の候補

コードを本格的に書く前に、小さく試して結果をユーザーに報告する。

- 2 番目以降の文節について、読みを左の文脈付きで変換し直して候補を作れるか、速さは十分か
- 途中の文節で候補を選んだあと、続けて入力すると何が起きるか。エンジンを変えずに選んだ候補を保つ方法はあるか
- `Candidate.value` で自信の低さを判定できそうか（Zenzai 有効時）
- 報告後、仕様 7. の未決定事項 1〜3 をユーザーと決める

## P2 候補の選択

- 対象の文節の決め方（仕様 3.）を実装する
- 候補リスト（上位 4 件・広げると最大 9 件・三角つき・左端を列にそろえる）を出す
- ↑ ↓ / Space / Tab / Esc / Enter / ← → を仕様 4. どおりにする。数字キーは P2a の結論に従う
- キー操作による状態の変化は `Core` の純粋な関数（状態とキー → 新しい状態）として実装し、テストする
- 完了条件
  - [x] キー操作の状態の変化のテスト
  - [x] 実機で、誤変換を ← → と ↑ ↓ で直して確定できる（ユーザー確認）

## P3 自信の印と意味の手がかり

- 自信の低い文節の印（仕様 2.2）を出す。判定方法は P2a の結論に従う
- 意味の手がかりの出典をプロトコルにし、最初の実装として同梱の対応表を用意する
- 完了条件
  - [x] 判定と手がかりのテスト
  - [ ] 実機で「はしを」などの同音異義語に手がかりが出る（ユーザー確認）

## P4 区切りの変更

- ⇧← → で対象の文節の区切りを伸び縮みさせる
- 既存の `editSegment(count:)` との関係を整理する。エンジンの変更が必要になったら止めて報告する
- 完了条件
  - [x] 区切りの変更のテスト
  - [ ] 実機で区切りを直して確定できる（ユーザー確認）

## 進み具合のメモ

- P0〜P4 は、それぞれ `feature/panel-p0-config` → `p1-display` → `p2a-research` → `p2-select` → `p3-confidence` → `p4-boundary` の順に積んだブランチで進めた
- 実機の確認は Claude が computer use で行った（P1・P2）。P3・P4 は Core のテストと開発用インストールまで済み、実機での確認はまだ
- 実装中に決めた小さなことは、仕様の「8. 実装メモ」にまとめた
